# AI 소비 피드백 판정 기준 (#140)

사용자에게 나간 피드백 문장이 **맞는지** 사람이 판정하는 기준입니다.
#111·#122 실험에서 판정한 사례(커밋 메시지에 기록)를 모아 정리했습니다.

## 판정 방법

1. 자기 판정 화면을 브라우저(크롬·엣지)로 엽니다. 판정자 1은 `판정자1.html`(전체), 판정자 2는 `판정자2.html`(그중 일부)입니다.
   - 왼쪽은 응답, 오른쪽은 그 응답을 만든 분석 재료입니다.
   - 응답의 숫자를 누르면 분석 재료에서 같은 숫자를 찾아 표시합니다. 찾지 못하면 반올림한 표현인지 확인하세요.
2. **분석 재료만 근거로** 판정합니다. 실제 거래 내역이나 다른 항목은 보지 않습니다.
3. 아래 오류가 **하나라도 있으면 X**, 없으면 O를 누릅니다. 기준이 헷갈리면 **애매**를 누르고 메모를 남깁니다.
   - X이면 오류 유형을 하나 이상 체크합니다.
   - 단축키: `1` O, `2` X, `3` 애매, `←` `→` 이동, `Enter` 다음 미판정
4. 판정은 브라우저에 자동 저장되니 중간에 닫아도 됩니다. 다 끝나면 **결과 CSV 저장**을 눌러 `판정자N_결과.csv`를 전달합니다.
   - 다른 브라우저나 PC에서 이어서 하려면, 저장한 CSV를 **CSV 불러오기**로 엽니다.
   - 브라우저 기록을 지우면 자동 저장도 지워지니, 중간중간 CSV로 저장해 두세요.
5. 지켜야 할 것
   - `_key/` 폴더는 열지 않습니다. 버전 정보가 들어 있습니다.
   - 다른 판정자와는 둘 다 끝날 때까지 상의하지 않습니다.

`판정자N.csv`와 `items/`는 같은 내용의 예비 자료입니다. 엑셀로 판정할 경우 `판정(O=맞음, X=틀림)`·`오류 유형`·`메모` 칸에 적고 **CSV UTF-8** 형식으로 저장합니다.

## 틀림(X) 유형

| 코드 | 유형 | 예 |
|---|---|---|
| `숫자출처` | 분석 재료에 없는 금액·건수·비율, 또는 다른 값을 가져다 씀 | 식대 이번 주 지출 124,200원을 "식대 12만 원 넘게 초과"로 씀 (실제 초과 119,176원) |
| `대상기준` | 비율·배수의 대상이나 기준을 잘못 붙임 | 이번 달 예산 비율을 "이번 주는 예산의 41%"로, 한 건 배수를 "평소의 N배"로 (주간 금액으로 읽힘). 이번 주 금액과 이번 달 누적 비율을 한 문장에 써서 비율이 이번 주 것으로 읽힘 ("이번 주 37만 원을 써서 이번 달 예산의 30%를 썼어요" → "지금까지 이번 달 예산의 30%"라고 해야 함). 이번 주 지출은 줄었는데 이번 달 속도(보통 이맘때보다 빠름)와 반대로 "이번 주는 속도가 느려졌어요", 이번 주 지출이 전주보다 크게 줄었는데 이번 달 속도("평소와 비슷")를 붙여 "이번 주는 평소처럼 지냈어요"처럼 이번 주 수치와 어긋나게 씀. 전주 비교를 "평소보다"로 씀 |
| `기간` | 기간을 잘못 표현함 | 월말 **예상** 초과를 "이번 달 누적됐어요"로, 남은 기간 절약액을 "매달"·"월 N원"으로, 카테고리의 월말 예상 초과액(예산 대비)을 "월말까지 N원이 더 나갈"로 (앞으로 쓸 금액이 아님) |
| `절약효과` | 절약 금액이나 효과를 잘못 말함 | 다 지켜도 초과가 남는데 "예산 안에 들어와요"·"크게 낮출 수 있어요", 일부 카테고리만 말하며 전체 효과를 붙임, 절약 금액을 액션에 없는 카테고리에 붙임, 절약 액션이 없는 주에 절약액을 지어냄 |
| `사실반대` | 사실과 반대로 말함 | 초과 예상인데 "예산 안에서 잘 쓰고 계세요", 비율이 올랐는데 "104%까지 내려왔어요" |
| `건수` | 거래처·결제 수단 건수가 틀림 | "카카오페이·토스페이 결제가 7건" (실제 3 + 3 = 6) |
| `내부용어` | 분석용 표기가 그대로 나옴 | "절약 액션", "MTD", 영문 감정 태그(`SATISFIED`), "태그"라는 말("모두 만족 태그라" → "모두 만족한 지출이라"), 대괄호 표기, 마크다운 제목(`# …`) |
| `톤` | 체념하거나 부적절한 말투 | "이번 달은 받아들이고", "다 메우긴 어려워 보여요" |
| `원인` | 원인을 분석 재료와 다르게 연결함 | 분석 재료는 "횟수 증가"인데 "건당 금액이 커져서"로 설명 |
| `기타` | 위에 없는 오류 (메모에 설명) | |

## 틀림이 아닌 것 (O)

아래 중 일부는 #140 판정 중 판정자가 정한 기준입니다 (2026-11-18).

- 만원·천원 단위로 내리거나 올린 표현이 원래 값과 10% 이내: 117,266원을 "11만 원 넘게", 8,557원을 "8천 원 정도"
- "N만 원대" 구간 안의 값: 74만 원을 "70만 원대"
- 배수를 반올림했지만 실제 값에서 벗어나지 않음: 5.9배를 "6배쯤"
- 대상을 밝힌 비율: "이번 주는 이번 달 예산의 15%를 써서"
- "N건 중 M건"에서 뒤 숫자가 맞음: "12건 중 10건"(실제 7 + 3 = 10)
- 반올림이 10%를 살짝 넘는 정도: 34,205원을 "3만 원"
- 이번 달 속도를 이번 주에 붙였지만 이번 주 수치와 방향이 같음: 이번 주 지출도 늘었고 이번 달 속도도 빠른데 "이번 주는 평소보다 쓰는 속도가 빨랐어요"
- 월말 예상값을 이미 일어난 일처럼 씀: "저축 목표에서 24만 원 멀어진 상태예요" (값은 "이대로면" 예상)
- 이전 값이 재료에 없는데 "늘었어요·커졌어요"라고 씀
- 절약 금액 없이 효과만 말하거나 "꽤·많이"처럼 표현함: 금액은 절약 시뮬레이션 화면에서 보여 줌 (단, 효과 자체가 틀리면 `절약효과`)
- "1.8배 늘었다"처럼 배수에 "늘었다"를 붙임
- 문장이 어색하거나 길기만 한 것은 내용 오류가 아닙니다. 말투 품질은 따로 봅니다.

## 집계

```
./gradlew judge -Pcmd=export -Pout=<폴더> -Pkinds=주간 -Psubset=70 -Plogs="v3.0=a.log;v3.9=b.log;v4.1=c.log"
./gradlew judge -Pcmd=score -Pkey=<폴더>/_key/key.csv -Psheets="판정자1_결과.csv;판정자2_결과.csv" -Preport=report.md
```

- 결과: 버전별 오류율, Wilson 95% 구간, 주차 단위 부트스트랩 95% 구간, 버전 간 Fisher 검정, 판정자 일치도(Cohen's κ), 불일치 항목 목록
- 불일치 항목은 두 판정자가 함께 다시 보고 합의한 시트를 만든 뒤 `-Pfinal=<합의>.csv`로 최종 집계합니다.
