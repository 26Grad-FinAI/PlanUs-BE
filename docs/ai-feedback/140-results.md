## 판정 방법

1. **블라인드 시트**: 세 버전 응답 207개를 섞어 J001~J207로 번호만 붙임. 버전 정보는 판정이 끝날 때까지 열지 않음 (`./gradlew judge -Pcmd=export`)
2. **사람 판정 → 기준 정리**: 판정자 1이 직접 24건 + 애매한 유형의 대표 34건을 판정하고, 유형별 규칙(A~I)을 기준서에 반영. 판정자 2는 20건 판정
3. **LLM 판정기**: 기준서를 시스템 프롬프트로 쓰는 claude-opus-5-5 판정기(구조화 출력)로 207건 전체 판정 (`./gradlew judge -Pcmd=llm`)
4. **판정기 검증**: 아무도 보지 않은 30건을 무작위로 뽑아 판정자 1이 판정기 결과를 보지 않고 판정 → 비교 → 불일치만 합의
5. **오류를 두 단계로 집계**: 사람 판정과 맞춰 본 결과, 판정자는 "사용자가 숫자·사실을 잘못 알게 되는 오류"만 X로 봤다
   - 사실 오류: 숫자출처·대상기준·기간·건수·내부용어
   - 조언 품질: 원인·절약효과·사실반대·톤 (별도 지표)

## 해석

1. **#122의 개선은 실제로 있었다.** 절약효과·기간·내부용어·원인 오류가 줄어 조언 품질 오류 31.9% → 8.7%, "이번 주 … N%" 패턴을 뺀 사실 오류 42.0% → 23.2%.
2. **#122가 새 오류를 만들었다.** 분석 재료에 `[예산 사용 비율 — 지금까지 이번 달 예산의 N%]`를 넣은 뒤 LLM이 이 누적 비율을 "이번 주"에 붙여 쓰는 응답이 1 → 27건으로 늘었다. 분석 재료에는 누적 비율만 있어 이 N%는 사실상 항상 누적인데, 205609a에서 "이번 주는 이번 달 예산의 15%를 써서"를 맞는 표현으로 보고 검사를 완화했다 (그 주의 15%는 누적이었고 이번 주 지출은 예산의 약 40%).
3. **v3.9 → v4.1에서 이번 주 총지출 누락이 36% → 87%로 늘었다.** 원인은 #132(톤 개편)로 **추정한다** — 프롬프트의 좋은 예에 이번 주 총지출이 없고(총지출이 있는 문장은 나쁜 예), 이번 달 속도를 "이번 주는"에 붙이며, "숫자 2~3개" 규칙이 추가됐다. 다만 두 버전 사이에는 #131·#138도 있어 통제된 비교는 아니다 (#138은 추세 문구 한 줄, #131은 절약 카드라 주간 문장 구성과는 거리가 멀다). #144에서 프롬프트 예시만 바꿔 다시 재면 확인된다. #132 측정은 길이·숫자 개수만 봐서 이 변화를 잡지 못했다.
4. **"47% → 12%"는 현재 기준으로 재현되지 않는다.** 블라인드·현재 기준으로 v3.9는 사실 오류 58%, 2번 패턴을 빼면 23%.

후속: 2·3번은 #144에서 고친다 (기준선: v4.1 사실 오류 43.5%, 조언 품질 13.0%, 총지출 누락 87.0%). 판정 중 나온 분석 로직 문제(만족 70% 일괄 제외, 기타 예산 0원 등)는 #141.

## 재현

```
# 1. 세 버전 측정 로그 (위 표의 커밋마다 체크아웃해서, ANTHROPIC_API_KEY 필요)
LLM_REPEAT=3 ./gradlew testLlm --tests "*ProductionPathValidationTest.productionPath_render"

# 2. 블라인드 시트 (주간만, 판정자 2용 70건)
./gradlew judge -Pcmd=export -Pout=<폴더> -Pkinds=주간 -Psubset=70 -Plogs="v3.0=a.log;v3.9=b.log;v4.1=c.log"

# 3. LLM 판정기 (중단 후 다시 실행하면 남은 항목만 호출)
#    <결과>.csv와 함께 지표별 시트 <결과>_사실오류.csv · _조언품질.csv · _총지출누락.csv 생성
./gradlew judge -Pcmd=llm -Pdir=<폴더> -Pout=<결과>.csv

# 4. 일치도 (버전 정보 없이) / 버전별 집계
./gradlew judge -Pcmd=agree -Psheets="<사람>.csv;<결과>_사실오류.csv"
./gradlew judge -Pcmd=score -Pkey=<폴더>/_key/key.csv -Psheets="<결과>_사실오류.csv"
```

측정 로그·판정 시트·판정기 원본 응답은 거래 메모(실명 등)가 들어 있어 저장소에 올리지 않았다. 판정기 비용은 207건에 약 $4.3 (프롬프트 캐싱으로 기준서 재사용). 판정기는 기준서(`judging-rubric.md`)의 지문이 바뀌면 이전 판정을 재사용하지 않는다 — 이 결과는 커밋 `c4696c2`의 기준서로 판정했다.
